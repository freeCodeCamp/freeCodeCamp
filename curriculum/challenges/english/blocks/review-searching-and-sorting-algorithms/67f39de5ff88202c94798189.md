## Searching Algorithms

Searching algorithms let you search for a target within a certain list of items.

In computer science, there are two searching algorithms you should know about. They are **linear search** and **binary search** algorithms. It is important to understand the differences between the two algorithms and when to use each one.

### Linear Search

- **Linear Search Algorithm**: Iterates through a list of items, checking each item from the beginning until the target item is found.
- **Successful Search Return**: If the target item is found, the index where it is located in the list is returned.
- **Unsuccessful Search Sentinel (`-1`)**: If the target is not found, it returns `-1`. In Python, `-1` is also a valid index referencing the last element of a nonempty list, so you must always check whether the result is `-1` before indexing to avoid accidentally retrieving the final element.
- **Linear Search Efficiency**: Because linear search checks each item until it finds the target, it is not efficient for a large list of items.
- **Linear Search Time Complexity**: The time complexity of linear search is `O(n)` because the time it takes to search through the list grows linearly with the size of the list.
- **Linear Search Space Complexity**: The space complexity of linear search is `O(1)` because it uses a constant amount of extra space for local variables (like the loop iterator `i`), independent of input size.

### Binary Search

- **Binary Search Algorithm**: Works by dividing a list of items in half and checking if the target value is in the middle of the list.
- **Sorted Input Prerequisite**: The condition for binary search to work is that the items in the list must be sorted in ascending order.
- **Efficiency Advantage**: Binary search is more efficient for searching through a large list because it divides the list in half and ignores any half where the target is not found.
- **Midpoint and Boundary Updates**: Calculates a midpoint index (`mid = (low + high) // 2`). Comparisons update search boundaries (`low = mid + 1` or `high = mid - 1`) until the search range is exhausted (`low > high`).
- **Path Tracing and Return Conventions**: Implementations may return an index or `-1`, or perform path tracing by recording visited midpoint values in a list along with status messages.
- **Binary Search Unsuccessful Result**: If the target item is finally not found in the list, it returns `-1`.
- **Binary Search Time Complexity**: The time complexity of binary search is `O(log n)` because the time it takes to search through the list grows logarithmically with the size of the list.
- **Binary Search Space Complexity**: The space complexity of binary search is `O(1)` because it uses a constant amount of extra space for variables like `low`, `high`, and `mid`.

### How Linear Search Differs from Binary Search 

- **Prerequisites**: Linear search does not require a sorted list, whereas binary search strictly requires input data to be sorted in ascending order.
- **Scalability**: Binary search is significantly more suitable for large lists of items compared to linear search.
- **Time Complexity Comparison**: The time complexity of linear search is `O(n)`, while binary search scales logarithmically at `O(log n)`.

## Sorting Algorithms and Divide-and-Conquer

In computer science, divide-and-conquer is a technique used to break down a problem into smaller sub-problems so they are easier to solve. Recursion is the technique often employed in divide-and-conquer, and divide-and-conquer is a powerful strategy used to implement many efficient sorting algorithms like merge sort.

### Merge Sort

- **Merge Sort Definition**: A sorting algorithm that follows the divide-and-conquer approach.
- **Base Case**: Stops recursion for lists of length zero or one, treating them as already sorted.
- **Recursive Splitting**: Recursively divides a list into sliced halves until each sub-list reaches the base case.
- **Merge Procedure**: Compares next elements of sorted halves, copies the smaller element into position (advancing its index), and copies any remaining elements. Implementations may return a newly constructed list or write sorted values back in-place into the original array.
- **Merge Sort Time Complexity**: The time complexity for merge sort is `O(n log n)` because the list is continuously divided in half (`log n`) and then merged together (`O(n)`).
- **Merge Sort Space Complexity**: The space complexity of merge sort is `O(n)` due to auxiliary storage required for slicing and merging sub-lists.
