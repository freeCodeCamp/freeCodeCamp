## Searching Algorithms

- **Purpose**: Searching algorithms let you search for a target within a list of items.
- **Types of Searching Algorithms**: Two common searching algorithms are Linear Search and Binary Search. Understanding their differences helps determine when to use each one.

### Linear Search

- **Linear Search Algorithm**: Iterates through a list of items, checking each item from the beginning until the target is found.
- **Successful Search**: If the target item is found, the index where it is located in the list is returned.
- **Unsuccessful Search**: The lecture implementations return `-1` to indicate that the target was not found. In Python, `-1` also indexes the last element of a nonempty list, so check whether the result is `-1` before using it as an index. Otherwise, an unsuccessful search could retrieve the last element by mistake.
- **Efficiency**: Because Linear Search checks each item sequentially, it can be inefficient for large lists.
- **Time Complexity**: `O(n)` because the time required to search grows linearly with the size of the list.
- **Space Complexity**: `O(1)` because it uses a constant amount of additional space regardless of the input size.

### Binary Search

- **Binary Search Algorithm**: An efficient searching algorithm that repeatedly divides a sorted list into halves to find a target value.
- **Sorted Input Prerequisite**: Binary Search requires the input list to be sorted in ascending order.
- **Search Range Initialization**: Initialize `low = 0` as the index of the first element and `high = len(arr) - 1` as the index of the last element. These variables define the inclusive range being searched.
- **Search Continuation Condition**: Continue searching while `low <= high`. If `low > high`, the search range is empty, meaning the target was not found.
- **Midpoint Calculation**: Calculate the middle index using integer division: `mid = (low + high) // 2`.
- **Target Comparison**: Compare the target value with `arr[mid]`. If they are equal, the target has been found at index `mid`.
- **Lower Boundary Update**: If `arr[mid] < target`, the target must be in the right half if it exists in the list. Update `low = mid + 1` to exclude the midpoint and all elements before it.
- **Upper Boundary Update**: If `arr[mid] > target`, the target must be in the left half if it exists in the list. Update `high = mid - 1` to exclude the midpoint and all elements after it.
- **Lecture Successful Search**: The lecture implementation returns the index of the target when it is found.
- **Lecture Unsuccessful Search**: The lecture implementation returns `-1` when the search range becomes empty.
- **Workshop Path Tracking**: The workshop implementation initializes an empty `path_to_target` list and appends the value at each visited midpoint during the search.
- **Workshop Successful Search**: When the target is found, the workshop returns a tuple containing `path_to_target` and a message indicating the index where the target was found.
- **Workshop Unsuccessful Search**: When the search range becomes empty, the workshop returns an empty list and a `"Value not found"` message.
- **Time Complexity**: `O(log n)` because the search range is approximately halved after each comparison.
- **Space Complexity**: The lecture implementation uses `O(1)` auxiliary space for variables such as `low`, `high`, and `mid`. The workshop implementation uses `O(log n)` auxiliary space because `path_to_target` stores the midpoint values visited during the search.

### How Linear Search Differs from Binary Search

- **Prerequisites**: Linear Search does not require a sorted list, whereas Binary Search requires the input data to be sorted in ascending order.
- **Scalability**: Binary Search is more suitable for large lists of items compared to Linear Search.
- **Time Complexity Comparison**: Linear Search has a time complexity of `O(n)`, while Binary Search has a time complexity of `O(log n)`.

## Sorting Algorithms and Divide-and-Conquer

- **Divide-and-Conquer**: A technique used to break down a problem into smaller sub-problems so they are easier to solve. Recursion is often employed to implement this approach, which is commonly used in efficient sorting algorithms such as Merge Sort.

### Merge Sort

- **Merge Sort Algorithm**: A sorting algorithm that follows the divide-and-conquer approach.
- **Base Case**: Lists with zero or one element are already sorted, so recursion stops when `len(array) <= 1`.
- **Dividing the List**: Split the list into two sliced halves and recursively sort each half.
- **Merging the Sub-lists**: Compare the next unmerged elements of the two sorted halves, copy the smaller element into the next output position, and advance its index. Once one half is exhausted, copy all remaining elements from the other half.
- **Workshop Implementation**: The workshop creates sliced halves and writes the merged values back into the original list, advancing `sorted_index` after each write. Modifying the original list does not make this an in-place sorting algorithm because the sliced halves require additional storage.
- **Time Complexity**: `O(n log n)` because the list is repeatedly divided into halves (`log n` levels), and merging the elements at each level takes `O(n)` time.
- **Space Complexity**: `O(n)` because Merge Sort requires additional memory to merge the sub-lists and is not an in-place sorting algorithm.
