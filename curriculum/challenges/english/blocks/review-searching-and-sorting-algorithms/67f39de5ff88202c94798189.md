## Searching Algorithms

Searching algorithms let you search for a target within a certain list of items.

In computer science, there are two searching algorithms you should know about. They are **linear search** and **binary search** algorithms. It is important to understand the differences between the two algorithms and when to use each one.

### Linear Search

- Linear search iterates through a list of items, checking each item from the beginning until the target item is found.
- If the target item is found, the index where it is located in the list is returned.
- **Not found:** If the target is not found, it returns `-1`, which is used as a sentinel value to indicate "not found". In Python, `-1` is also a valid index that refers to the last item of a nonempty list. Always check whether the result is `-1` before using it to index the list. Otherwise, an unsuccessful search could accidentally return the last item.
- Because linear search checks each item until it finds the target, it is not efficient for a large list of items.
- The time complexity of linear search is  `O(n)` because the time it takes to search through the list grows linearly with the size of the list.
- **Space complexity:** The space complexity of linear search is `O(1)` because it uses a constant amount of extra space for the loop variable `i`. This amount of extra storage does not grow with the length of the list.

### Binary Search


- **Working:** Binary search works by repeatedly dividing a sorted list into halves and checking the middle element.
- **Requirement:** The implementations taught in the lecture and workshop require the list to be sorted in ascending order.
- **Initialization:** The algorithm initializes `low` to `0` and `high` to `len(arr) - 1`, representing the current search range.
- **Midpoint:** It calculates the middle index using `mid = (low + high) // 2`.
- **Comparison:** If the middle element matches the target, the target is found.
- **Right half:** If the middle element is smaller than the target, `low` is updated to `mid + 1`.
- **Left half:** If the middle element is greater than the target, `high` is updated to `mid - 1`.
- **Termination:** The search continues while `low <= high`. If `low` becomes greater than `high`, the search range is empty and the target is not found.
- **return value:** The lecture implementation returns the target's index when found and `-1` when it is not found.
- **Workshop path tracing:** The workshop implementation appends each visited midpoint value to `path_to_target`. When the target is found, it returns `path_to_target` and a message containing the target's index. If the target is not found, it returns an empty list and `"Value not found"`.
- **Time complexity:** The time complexity of binary search is `O(log n)` because each comparison reduces the remaining search range by approximately half.
- **Space complexity:** The space complexity of the lecture implementation is `O(1)` because it uses a constant amount of extra space for the `low`, `high`, and `mid` variables. This amount does not grow with the input size.

### How Linear Search Differs from Binary Search 

- **Input requirement:** Linear search does not require sorted input, whereas binary search requires the input list to be sorted in ascending order for the implementations taught in this module.

- Binary search is more suitable for a large list of items compared to linear search.
- The time complexity of linear search is  `O(n)` because the time it takes to search through the list grows linearly with the size of the list.
- The time complexity of binary search is `O(log n)` because the time it takes to search through the list grows logarithmically with the size of the list.

## Sorting Algorithms and Divide-and-Conquer

In computer science, divide-and-conquer is a technique used to break down a problem into smaller sub-problems so they are easier to solve. Recursion is the technique often employed in divide-and-conquer, and divide-and-conquer is a powerful strategy used to implement many efficient sorting algorithms like merge sort.

### Merge Sort

- **Working:** Merge sort is a sorting algorithm that follows the divide-and-conquer approach.
- **Base case:** The algorithm stops dividing when a sub-list contains zero or one element because such a sub-list is already sorted.
- **Dividing:** It finds the middle of the list and recursively sorts the left and right halves using slices of the original list.
- **Merging:** It compares the first unmerged elements of the two sorted halves and copies the smaller element into the merged list. It then advances the index of the half from which the element was copied.
- **Remaining elements:** After one half has no remaining elements, the algorithm copies all remaining elements from the other half into the merged list.
- **Workshop implementation:** The workshop implementation writes the merged values back into the original list using the sorted halves.
- **Time complexity:** The time complexity of merge sort is `O(n log n)` because the list is divided in half at each level, resulting in `O(log n)` levels, and merging the elements at each level takes `O(n)` time.
- **Space complexity:** The space complexity of merge sort is `O(n)` because it creates additional lists for the divided halves and the merged result.
