# --description--

In Python, values are represented by objects, and variables are names that refer to those objects. Each object has a type, a value, and an identity. Identity distinguishes one object from another.

The identity operators let you check whether two names refer to the same object. The `is` operator returns `True` if they do, and `False` otherwise. The `is not` operator returns the opposite result.

```python
score = 80
saved_score = score

print(score is saved_score) # True
print(score is not saved_score) # False
```

Assigning `score` to `saved_score` makes both names refer to the same object. It does not create a separate copy of that object.

## Identity and Equality

Identity and equality answer different questions. The `==` operator checks whether values are equal, while `is` checks whether they belong to the same object. Similarly, `!=` checks for unequal values, while `is not` checks for different objects.

Two values can be equal without being the same object:

```python
whole_number = 5
decimal_number = 5.0

print(whole_number == decimal_number) # True
print(whole_number is decimal_number) # False
print(whole_number is not decimal_number) # True
```

Here, the integer and the float have equal numeric values. They must be different objects because one is an integer and the other is a float.

However, separate assignments do not necessarily create separate objects. CPython, the most widely used implementation of Python, caches some small integers. This means it keeps those objects available and reuses them instead of creating new ones. For example, in CPython:

```python
whole_number = 3
other_whole_number = 3

print(whole_number == other_whole_number) # True
print(whole_number is other_whole_number) # True
```

Both names refer to the cached object for `3`. Even converting the string `'3'` with `int('3')` reuses that object in CPython.

This does not mean all equal integers share an object. For example, these separate conversions create distinct objects in CPython:

```python
first_number = int('99999')
second_number = int('99999')

print(first_number == second_number) # True
print(first_number is second_number) # False
```

The caching rules are implementation details, not guarantees of the Python language. They can differ between implementations and versions. Other optimizations can also reuse integer objects, so you should not assume that larger numbers always have different identities.

Python implementations can reuse string objects too. Two variables containing equal strings might refer to the same object or to separate objects.

**Use `==` and `!=` to compare number and string values, not `is` and `is not`.** An identity comparison might appear to work for some values because of object reuse, then give a different result for other equal values. Equality comparisons express what you actually want to check.

If you use `is` directly with a numeric or string literal, Python warns you about this likely mistake:

```python
whole_number = 3
print(whole_number is 3)
```

This produces a warning like the following:

```md
SyntaxWarning: "is" with a literal. Did you mean "=="?
```

A warning does not stop the code from running, but this comparison should use `whole_number == 3` to check the value. The earlier comparison between two variables does not produce this warning, even though identity is still the wrong choice for comparing their numeric values.

## Checking for a Missing Value

One common use of identity operators is checking for `None`. Python provides this special object to represent the absence of a value. There is only one `None` object, so you can use `is None` and `is not None` to check for it. Unlike integer caching, this is a Python language guarantee.

```python
result = None

print(result is None) # True
print(result is not None) # False
```

`None` is falsy, but it is not the same object as other falsy values such as `0` or `False`:

```python
zero = 0
flag = False
missing = None

print(bool(zero)) # False
print(bool(flag)) # False
print(bool(missing)) # False
print(zero is flag) # False
print(zero is missing) # False
print(flag is missing) # False
```

This distinction matters when zero is a valid result. For example, a score of zero means a score has been recorded, while `None` can mean no score is available yet:

```python
score = 0

if score is None:
    print('No score available')
else:
    print('Score:', score) # Score: 0
```

Using `if not score` instead would treat both `0` and `None` as missing. Use `is None` when you need to distinguish absence from a valid falsy value. Use `is not None` when you want to check that a value is present.

`True` and `False` are also each a single, guaranteed object. Objects like these and `None` are called singletons. However, for ordinary boolean flags, continue using direct truth tests such as `if is_ready` or `if not is_ready`, rather than comparing with `True` or `False` using identity operators.
