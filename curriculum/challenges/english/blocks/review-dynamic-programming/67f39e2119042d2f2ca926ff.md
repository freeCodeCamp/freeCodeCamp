## Introduction to Dynamic Programming

- **Definition**: Dynamic programming is an algorithmic technique that solves complex problems by breaking them down into simpler subproblems and storing the results to avoid redundant calculations. 
- **Overlapping Subproblems**: The same smaller problems appear multiple times when solving the larger problem. Instead of recalculating these subproblems repeatedly, we store their solutions.
- **Optimal Substructure**: The optimal solution to the problem contains optimal solutions to its subproblems. This means we can build up the best solution by combining the best solutions to smaller parts.

## Dynamic Programming Solutions

- **Climbing Stairs Problem**: The examples in this section solve the same problem: for a positive number of steps `n`, count the distinct ways to reach the top when each move climbs either one or two steps. The last move reaches step `n` from either step `n - 1` or step `n - 2`, so the number of ways to reach step `n` is the sum of the counts for those two steps.

- **Memoization (Top-Down Approach)**: Memoization stores the results of expensive function calls and returns the cached result when the same inputs occur again. 

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

- **Tabulation (Bottom-Up Approach)**: Tabulation builds the solution from the ground up, filling a table with solutions to subproblems.

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

- **Constant-Space Tabulation**: Each new count depends only on the previous two counts, so the full table can be replaced with two variables:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n

    prev2, prev1 = 1, 2  # Only store last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

## Comparing Time and Space Complexity

These are the complexities for the climbing stairs solutions, treating each arithmetic operation as constant time and each stored count as one unit of space:

- **Naive Recursion**: The time complexity has an upper bound of `O(2^n)` because the same subproblems are solved repeatedly.
- **Memoization**: With an initially empty cache, the time complexity is `O(n)` because each step count is calculated once. The space complexity is `O(n)` for the memo dictionary and the recursive call stack.
- **Tabulation**: The time complexity is `O(n)`, and the space complexity is `O(n)` for the list. Because tabulation is iterative, it avoids the growth of a recursive call stack.
- **Constant-Space Tabulation**: The time complexity is `O(n)`, and the auxiliary space complexity is `O(1)` because only the previous two counts are stored.

## Coin Change Problem

The coin change problem asks for the minimum number of coins needed to make a target amount. Here is how the dynamic programming solution works:

- **Base Case**: Making an amount of `0` takes zero coins, so `dp[0]` is `0`.
- **Initialization**: Every other amount starts at infinity, which marks it as unreachable until a combination of coins is found.
- **Recurrence**: For each amount `i`, take the minimum of `dp[i - coin] + 1` over every denomination that doesn't exceed `i`.
- **Unreachable Amounts**: If the target amount is still infinity at the end, no combination of coins can make it, so the function returns `-1`.
- **Complexity**: The time complexity is `O(amount * number_of_coins)`, and the space complexity is `O(amount)` for the `dp` list.

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0

    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)

    return dp[amount] if dp[amount] != float('inf') else -1

print(min_coins(6, [1, 3, 4]))  # 2 (3 + 3)
print(min_coins(3, [2]))  # -1
```

## Real-World Applications Using Dynamic Programming

- **Route Optimization**: GPS systems use dynamic programming algorithms to find shortest paths between locations.
- **Text Processing**: Spell checkers and autocomplete features often rely on dynamic programming to calculate edit distances between words.
- **Financial Modeling**: Investment strategies and portfolio optimization frequently employ dynamic programming techniques.
- **Resource Allocation**: The knapsack problem and its variants appear in scheduling, budgeting, and resource management.

## When to Use Dynamic Programming

You should consider using dynamic programming in the following scenarios:

- The problem can be broken down into overlapping subproblems.
- The problem exhibits optimal substructure.
- A naive recursive solution would involve repeated calculations.
- You need to optimize for time complexity at the cost of space complexity.

Common dynamic programming patterns include:

- **Optimization Problems**: These seek a minimum or maximum value, such as the fewest coins needed to make an amount.
- **Counting Problems**: These count the possible ways to achieve something, such as the ways to climb a staircase.
- **Decision Problems**: These determine whether a solution satisfying given conditions exists, producing a yes-or-no answer. Dynamic programming can solve suitable decision problems by combining answers to smaller subproblems.
