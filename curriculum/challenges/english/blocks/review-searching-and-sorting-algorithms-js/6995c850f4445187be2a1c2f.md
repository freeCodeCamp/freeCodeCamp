## Searching Algorithms

- **Purpose**: Searching algorithms let you search for a target within an array of items.
- **Types of Searching Algorithms**: Two common searching algorithms are Linear Search and Binary Search. Understanding their differences helps determine when to use each one.

### Linear Search

- **Linear Search Algorithm**: Iterates through an array of items, checking each item from the beginning until the target is found.
- **Successful Search**: If the target item is found, the index where it is located in the array is returned.
- **Unsuccessful Search**: The lecture implementations return `-1` to indicate that the target was not found, which represents an invalid index in JavaScript.
- **Efficiency**: Because Linear Search checks each item sequentially, it can be inefficient for large arrays.
- **Time Complexity**: `O(n)` because the time required to search grows linearly with the size of the array.
- **Space Complexity**: `O(1)` because it uses a constant amount of additional space regardless of the input size.

### Binary Search

- **Binary Search Algorithm**: An efficient searching algorithm that repeatedly divides a sorted array into halves to find a target value.
- **Sorted Input Prerequisite**: Binary Search requires the input array to be sorted in ascending order.
- **Search Range Initialization**: Initialize `low = 0` as the index of the first element and `high = arr.length - 1` as the index of the last element. These variables define the inclusive range being searched.
- **Search Continuation Condition**: Continue searching while `low <= high`. If `low > high`, the search range is empty, meaning the target was not found.
- **Midpoint Calculation**: Calculate the middle index using `Math.floor((low + high) / 2)`.
- **Target Comparison**: Compare the target value with `arr[mid]`. If they are equal, the target has been found at index `mid`.
- **Lower Boundary Update**: If `arr[mid] < target`, the target must be in the right half if it exists in the array. Update `low = mid + 1` to exclude the midpoint and all elements before it.
- **Upper Boundary Update**: If `arr[mid] > target`, the target must be in the left half if it exists in the array. Update `high = mid - 1` to exclude the midpoint and all elements after it.
- **Lecture Successful Search**: The lecture implementation returns the index of the target when it is found.
- **Lecture Unsuccessful Search**: The lecture implementation returns `-1` when the search range becomes empty.
- **Workshop Path Tracking**: The workshop implementation initializes an empty `pathToTarget` array and appends the value at each visited midpoint during the search using `pathToTarget.push(valueAtMiddle)`.
- **Workshop Successful Search**: When the target is found, the workshop returns an array containing `pathToTarget` and a message indicating the index where the target was found, e.g., `[pathToTarget, `Value found at index ${mid}`]`.
- **Workshop Unsuccessful Search**: When the search range becomes empty, the workshop returns an empty array and a `"Value not found"` message: `[[], "Value not found"]`.
- **Time Complexity**: `O(log n)` because the search range is approximately halved after each comparison.
- **Space Complexity**: The lecture implementation uses `O(1)` auxiliary space for variables such as `low`, `high`, and `mid`. The workshop implementation uses `O(log n)` auxiliary space because `pathToTarget` stores the midpoint values visited during the search.

### How Linear Search Differs from Binary Search

- **Prerequisites**: Linear Search does not require a sorted array, whereas Binary Search requires the input data to be sorted in ascending order.
- **Scalability**: Binary Search is more suitable for large arrays of items compared to Linear Search.
- **Time Complexity Comparison**: Linear Search has a time complexity of `O(n)`, while Binary Search has a time complexity of `O(log n)`.

## Sorting Algorithms and Divide-and-Conquer

- **Divide-and-Conquer**: A technique used to break down a problem into smaller sub-problems so they are easier to solve. Recursion is often employed to implement this approach, which is commonly used in efficient sorting algorithms such as Merge Sort.

### Merge Sort

- **Merge Sort Algorithm**: A sorting algorithm that follows the divide-and-conquer approach.
- **Base Case**: Arrays with zero or one element are already sorted, so recursion stops when `array.length <= 1`.
- **Dividing the Array**: Split the array into two sliced halves using `array.slice(0, middlePoint)` and `array.slice(middlePoint)` where `middlePoint = Math.floor(array.length / 2)`, and recursively sort each half.
- **Merging the Sub-arrays**: Compare the next unmerged elements of the two sorted halves, copy the smaller element into the next output position in `array[sortedIndex]`, and advance its index. Once one half is exhausted, copy all remaining elements from the other half.
- **Workshop Implementation**: The workshop creates sliced halves and writes the merged values back into the original array, advancing `sortedIndex` after each write. Modifying the original array does not make this an in-place sorting algorithm because the sliced halves require additional storage.
- **Time Complexity**: `O(n log n)` because the array is repeatedly divided into halves (`log n` levels), and merging the elements at each level takes `O(n)` time.
- **Space Complexity**: `O(n)` because Merge Sort requires additional memory to merge the sub-arrays and is not an in-place sorting algorithm.
