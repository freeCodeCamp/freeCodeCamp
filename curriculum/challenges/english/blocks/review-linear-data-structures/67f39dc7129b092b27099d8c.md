## Arrays

- **Static Arrays**: Have a fixed size determined at initialization. Elements are stored in adjacent memory locations, which makes access very efficient. Their size cannot be changed while the program is running.

- **Dynamic Arrays**: Can grow or shrink automatically while the program is running. When the array is full, its elements are copied into a new, larger array. The new size is chosen so that these expensive copies happen less frequently.

- **Static Arrays in Python**: Python does not include traditional static arrays as built-in data structures. Other languages, like Java, do support them.

### Python Lists (Dynamic Arrays)

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### Time Complexities for Dynamic Arrays

- **Access**: O(1)
- **Insert at end**: O(1) if there is space available, O(n) when resizing is needed
- **Insert in middle**: O(n) because the elements after it need to be relocated

### Choosing Between Static and Dynamic Arrays

- **Static Arrays**: When you know the number of elements in advance and need to access them frequently.
- **Dynamic Arrays**: When the number of elements is unknown or changes over time, or when you will be frequently inserting and deleting elements.

## Stacks

- **Stacks**: Last-In, First-Out (LIFO) data structure. Stacks have two ends, top and bottom. Elements are added and removed from the top only.

- **Push Operation**: Adding an element to the top of the stack. When using a Python list, this takes O(1) time if there is space available, or O(n) when resizing is needed.

- **Pop Operation**: Removing an element from the top of the stack. Time complexity: O(1). Space complexity: O(1).

```python
# Using a Python list as a stack, where the end of the list is the top
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operation
top_element = stack.pop()  # Returns 3
```

## Queues

- **Queues**: First-In, First-Out (FIFO) data structure. Queues have two ends, front and back. Elements are added to the back and removed from the front.

- **Enqueue Operation**: Adding an element to the back of the queue. When using a Python list, this takes O(1) time if there is space available, or O(n) when resizing is needed.

- **Dequeue Operation**: Removing an element from the front of the queue. The next element in line becomes the new front. Time complexity: O(1). Space complexity: O(1).

```python
# Using a Python list as a queue, where the start of the list is the front
queue = []

# Enqueue operations
queue.append(1)
queue.append(2)
queue.append(3)

# Front element
front_element = queue[0]  # 1

# Dequeue operation
front_element = queue.pop(0)  # Returns 1
```

- **Note**: Removing the first element of a Python list with `.pop(0)` relocates all the remaining elements, so it takes O(n) time.

## Linked Lists

- **Linked Lists**: Linear data structure where each node stores data and a reference to the next node. Nodes are connected like a chain. Linked lists don't have a fixed size and can grow or shrink by updating the connections between the nodes.

- **Common Uses**: Implementing other data structures, such as stacks, queues, and deques, and graph algorithms like depth-first search and breadth-first search.

### Singly Linked Lists

- **Structure**: Each node stores data and one reference to the next node.
- **Traversal**: Can only move forward, from head to tail.
- **Head Node**: First node in the list, usually the only directly accessible node. Traversal starts here.
- **Tail Node**: Last node in the list. Its reference to the next node is `None`, which marks the end of the list.

#### Inserting Nodes

- **Insert at beginning**: O(1) - connect the new node to the old head and make it the new head
- **Insert at end**: O(n) - must traverse to the end, then connect the tail to the new node
- **Insert in middle**: O(n) - must traverse to the position, then connect the previous node to the new node and the new node to the next node
- **Space complexity**: O(1) - only the new node is created

#### Removing Nodes

- **Remove from beginning**: O(1) - make the next node the new head
- **Remove from middle**: O(n) - must traverse to the node, then connect the previous node to the next node, forming a "bridge" over the removed node
- **Remove from end**: O(n) - must traverse to the end, then remove the connection of the previous node, making it the new tail
- **Space complexity**: O(1) - no additional memory is required

### Doubly Linked Lists

- **Structure**: Each node stores data and two references: one to the next node and one to the previous node.
- **Traversal**: Can move in both directions.
- **Tail Reference**: It's common to keep a reference to the tail node in the list itself. This allows adding nodes at the end in O(1) time, without traversing the list, and starting a traversal from the end.
- **Insertion and Deletion**: Work the same way as in singly linked lists, but two references per node need to be updated.
- **Memory**: Requires more memory than singly linked lists because each node stores two references instead of one.

## When to Use Each Data Structure

- **Static Arrays**: When the number of elements is known in advance and fast, frequent access is needed
- **Dynamic Arrays (Lists)**: When you need ordered, indexed access and don't know the size in advance
- **Stacks**: When the last element added should be the first one removed (LIFO)
- **Queues**: When elements should be processed in the order they were added (FIFO)
- **Singly Linked Lists**: When the size changes often and you mostly insert and remove at the beginning
- **Doubly Linked Lists**: When you need to traverse in both directions or add elements at the end efficiently, and the extra memory per node is acceptable
