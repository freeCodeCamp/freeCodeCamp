## Algorithms and Big O Notation

- **Algorithms**: A set of unambiguous instructions for solving a problem or carrying out a task. Algorithms must finish in a finite number of steps and each step must be precise and unambiguous.

- **Big O Notation**: Describes an asymptotic upper bound on an algorithm's resource usage as the input size increases. Big O measures this overall scaling trend separately from whether you are looking at a best, average, or worst-case scenario, while ignoring constant factors and smaller terms.

### Common Time Complexities

- **O(1) - Constant Time**: Algorithm takes the same amount of time regardless of input size.

```python
def check_even_or_odd(number):
    if number % 2 == 0:
        return 'Even'
    else:
        return 'Odd'
```

- **O(log n) - Logarithmic Time**: An upper bound on running time that grows at most logarithmically with input size. When the bound is tight, the algorithm runs in logarithmic time. This commonly occurs when the problem size is repeatedly reduced by a constant fraction, as in Binary Search.

- **O(n) - Linear Time**: An upper bound on running time that grows at most linearly with input size. When the bound is tight, running time grows proportionally to input size.

```python
for grade in grades:
    print(grade)
```

- **O(n log n) - Log-Linear Time**: Common in efficient divide-and-conquer sorting. Merge Sort has O(n log n) worst-case complexity. Quick Sort has O(n log n) average-case complexity, but its worst-case complexity is O(n²).

- **O(n²) - Quadratic Time**: An upper bound on running time that grows at most quadratically with input size. When the bound is tight, running time grows proportionally to the square of input size. This occurs in nested loops where each loop performs n iterations.

```python
for i in range(n):
    for j in range(n):
        print("Hello, World!")
```

- **O(2ⁿ) - Exponential Time**: An exponential upper bound on running time. When the bound is tight, the growth rate is proportional to 2ⁿ, which doubles whenever n increases by one.

- **O(n!) - Factorial Time**: A factorial upper bound on running time. When the bound is tight, the growth rate is proportional to n!, the number of permutations of n distinct items.

### Space Complexity

- **O(1) - Constant Space**: Memory usage is bounded by a constant independent of input size.

- **O(n) - Linear Space**: Memory usage grows at most linearly with input size. When the bound is tight, memory usage grows proportionally to input size.

- **O(n²) - Quadratic Space**: Memory usage grows at most quadratically with input size. When the bound is tight, memory usage grows proportionally to the square of input size.

- **O(2ⁿ) - Exponential Space**: An exponential upper bound on memory usage. When the bound is tight, memory usage grows proportionally to 2ⁿ.

- **O(n!) - Factorial Space**: A factorial upper bound on memory usage. When the bound is tight, memory usage grows proportionally to n!.

## Problem-Solving Techniques

- **Understanding the Problem**: Read the problem statement multiple times. Identify the input, expected output, and how to transform input to output.

- **Algorithm and Data Structure Selection**: Compare alternative algorithms by their time and space requirements, and choose data structures suited to the problem.

- **Pseudocode**: High-level description of algorithm logic that is language-independent, using common written language mixed with programming constructs like `IF`, `ELSE`, `FOR`, and `WHILE`.

```md
GET original_string
SET reversed_string = ""

FOR EACH character IN original_string:
    ADD character TO THE BEGINNING OF reversed_string

DISPLAY reversed_string
```

- **Implementation**: Write clean, readable, and modular code based on your pseudocode plan. Use appropriate built-in tools for common tasks.

- **Edge Cases**: Specific, valid inputs that occur at the boundaries of what an algorithm should handle. Always consider and test edge cases.

- **Testing and Refinement**: Test your code against the provided examples and edge cases. Debug errors, check the results, and refine the solution to improve clarity or efficiency.

## Arrays

- **Static Arrays**: Have a fixed size set when created, with elements stored in contiguous memory. This adjacent layout enables fast, constant-time indexed access (O(1)). Choose a static array when the maximum number of items is strictly known ahead of time.

- **Dynamic Arrays**: Can grow or shrink automatically during program execution. When they run out of space, they handle resizing under the hood by allocating a larger memory block and copying existing elements over.

**Note:** Python does not have a traditional built-in static array. Python lists are dynamic arrays.

### Python Lists (Dynamic Arrays)

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### Time Complexities for Dynamic Arrays

- **Access**: O(1)

- **Insert at end**: O(1) average, O(n) when resizing needed

- **Insert in middle**: O(n)

- **Delete**: O(n) for middle, O(1) for end

## Stacks

- **Stacks**: Last-In, First-Out (LIFO) data structure. Elements added and removed from the top only.

- **Push Operation**: Adding an element to the top of the stack. For the Python list implementation below, an ordinary push takes O(1) time and O(1) additional space. A push that requires resizing can take O(n) time and O(n) additional space.

- **Pop Operation**: Removing an element from the top of the stack. Time complexity is typically O(1), and the additional space required is usually O(1).

```python
# Using Python list as stack
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operations
top_element = stack.pop()  # Returns 3
```

## Queues

- **Queues**: First-In, First-Out (FIFO) data structure where elements are added to the back and removed from the front.

- **Enqueue Operation**: Adding an element to the back of the queue. Time complexity: O(1), Space complexity: O(1).

- **Dequeue Operation**: Removing an element from the front of the queue. Time complexity: O(1), Space complexity: O(1).

## Linked Lists

- **Linked Lists**: Linear data structure where each node contains data and a reference to the next node. Nodes are connected like a chain.

### Singly Linked Lists

- **Structure**: Each node has data and one reference to the next node.

- **Traversal**: Can only move forward from head to tail.

- **Head Node**: First node in the list, usually the only directly accessible node.

- **Tail Node**: Last node in the list, points to `None`.

### Linked List Implementation

- **Node Class**: A nested `Node` class represents individual nodes. Each node contains data and a reference to the next node.

- **Initialization**: The `head` reference starts as `None` because the list has no nodes. Each new node's `next` reference starts as `None` because it has no successor yet.

- **Length Tracking**: A length variable keeps track of the number of nodes in the list.

- **`is_empty()`**: Checks whether the list is empty by checking if `head` is `None`.

- **Appending**: Traverse from the head until reaching the last node, then update its `next` reference to point to the new node. If the list is empty, the new node becomes the head.

```python
class LinkedList:
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None

    def __init__(self):
        self.head = None
        self.length = 0

    def is_empty(self):
        return self.head is None

    def append(self, data):
        new_node = self.Node(data)

        if self.is_empty():
            self.head = new_node
        else:
            current = self.head

            while current.next:
                current = current.next

            current.next = new_node

        self.length += 1
```

### Operations and Time Complexities

- **Insert at beginning**: O(1)

- **Insert at end**: O(n) - must traverse to end

- **Insert in middle**: O(n) - must traverse to position

- **Delete from beginning**: O(1)

- **Delete from end**: O(n) - must traverse to find previous node

- **Delete from middle**: O(n) - must traverse to find node

### Insertion and Deletion

- **Insertion at Beginning**: Create a new node, set its `next` reference to the current head, and update the head to point to the new node.

- **Insertion at End**: Traverse to the last node and update its `next` reference to point to the new node.

- **Insertion in Middle**: Traverse to the node before the desired position. Update the new node's `next` reference to point to the next node, then update the previous node's `next` reference to point to the new node.

- **Deletion from Beginning**: Update the head to point to the second node.

- **Deletion from End**: Traverse to the second-to-last node and update its `next` reference to `None`.

- **Deletion from Middle**: Find the node before the target node and update its `next` reference to skip the target node.

- **Removing by Value**: Track the previous node while traversing. If the target is the head, update the head directly. If the value is not found, return without modifying the list or its length. Decrement the length only after a successful removal.

### Auxiliary Space Complexities

- **Insertion at beginning**: O(1) auxiliary space, excluding the storage required for the new node.

- **Insertion at end**: O(1) auxiliary space, excluding the storage required for the new node.

- **Insertion in middle**: O(1) auxiliary space, excluding the storage required for the new node.

- **Deletion from beginning**: O(1) auxiliary space.

- **Deletion from end**: O(1) auxiliary space.

- **Deletion from middle**: O(1) auxiliary space.

### Doubly Linked Lists

- **Structure**: Each node has data and two references: next node and previous node.

- **Traversal**: Can move in both directions.

- **Memory**: Requires more memory than singly linked lists due to extra reference.

- **Tail Reference**: Maintaining a reference to the last node allows reverse traversal using previous references.

## Hash Maps and Sets

### Maps and Hash Maps

- **Abstract Data Type (ADT) vs. Implementation**: An ADT defines the *interface*—specifying what operations a data structure supports and how it behaves logically. A concrete implementation defines the backend mechanism, showing *how* those operations are actually built and executed in memory.

- **Map (ADT)**: An abstract data type defining a collection of unique keys mapped to values. It sets the rules for what a map can do without dictating its internal storage.

- **Hash Map**: A concrete implementation of the Map ADT that uses a hash function to compute storage locations in an underlying array for fast lookups.

### Python Dictionaries (Hash Maps)

```python
# Creating dictionaries
my_dictionary = {
    "A": 1,
    "B": 2,
    "C": 3
}

# Alternative creation
my_dictionary = dict(A=1, B=2, C=3)

# Access and modify
value = my_dictionary["A"]  # 1
my_dictionary["A"] = 4      # Update value
del my_dictionary["A"]      # Remove key-value pair

# Check membership
"C" in my_dictionary

# Get keys, values, items
my_dictionary.keys()
my_dictionary.values()
my_dictionary.items()
```

### Time Complexities for Hash Maps

- **Average case**: O(1) for insert, get, delete

- **Worst case**: O(n) when many hash collisions occur

### Auxiliary Space Complexities for Hash Maps

- **Insertion**: O(1) additional space for ordinary insertion. Resizing may require O(n) additional space.

- **Lookup**: O(1) auxiliary space.

- **Deletion**: O(1) auxiliary space.

### Sets

- **Sets**: Unordered collections of unique elements. No duplicates allowed, no specific order maintained.

- **Set Elements**: Sets can contain numbers, strings, and tuples containing only numbers and strings. Lists, dictionaries, and other sets cannot be set elements. A tuple containing a list cannot be a set element, even though the tuple itself is immutable.

```python
# Creating sets
numbers = {1, 2, 3, 4}
empty_set = set()  # Must use set(), not {}

# Add and remove elements
numbers.add(5)
numbers.remove(4)      # Raises KeyError if not found
numbers.discard(4)     # No error if not found

# Remove and return an arbitrary element
numbers.pop()

# Remove all elements
numbers.clear()

# Get the number of elements
len(numbers)
```

### Set Operations

```python
set_a = {1, 2, 3, 4}
set_b = {2, 3, 4, 5, 6}

# Union, intersection, difference, symmetric difference
set_a.union(set_b)                  # or set_a | set_b
set_a.intersection(set_b)           # or set_a & set_b
set_a.difference(set_b)             # or set_a - set_b
set_a.symmetric_difference(set_b)   # or set_a ^ set_b

# Subset and superset checks
set_a.issubset(set_b)
set_a.issuperset(set_b)
set_a.isdisjoint(set_b)

# Membership testing
5 in numbers
```

### Time Complexities for Sets

- **Average case**: O(1) for add, remove, membership testing

- **Worst case**: O(n) due to hash collisions

- **Length lookup**: O(1) using `len()`.

### Auxiliary Space Complexities for Sets

- **Insertion**: O(1) additional space for ordinary insertion. Resizing may require O(n) additional space.

- **Lookup**: O(1) auxiliary space.

- **Deletion**: O(1) auxiliary space.

- **Length lookup**: O(1) auxiliary space.

## Hash Collisions

- **Hash Collision**: Different keys can produce the same hash value. In a hash table, collisions also occur when different hash values map to the same array index. Entries sharing an index must be handled by a collision resolution strategy.

- **Collision Resolution Strategies**:

  - **Chaining**: Each array index points to a linked list storing all entries that map to that same bucket index.

  - **Open Addressing**: Searches for the next available array index using a predefined sequence when a collision happens.

## When to Use Each Data Structure

- **Lists**: When you need ordered, indexed access and don't know size in advance.

- **Stacks**: For LIFO operations (undo functionality, expression evaluation, backtracking).

- **Queues**: For FIFO operations (task scheduling, breadth-first search).

- **Linked Lists**: When frequent insertion/deletion at beginning, unknown size, no random access needed.

- **Hash Maps**: For fast key-value lookups, counting occurrences, caching.

- **Sets**: For uniqueness checking, mathematical set operations, removing duplicates.
