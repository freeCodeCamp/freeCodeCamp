# --description--

Now, test the function with email `alejandro@edu.com` and `sofia@edu.com`, log the output in console like you
have done for `fatima@edu.com`.

This works, but the nested loops make it slow and hard to maintain. Every lookup requires traversing all 
`departments` → `programs` → `instructors` is O(n³) complexity. Adding a new department or program means
more iterations. If you need to search by room, department code, or instructor ID, you'd write nearly identical 
nested loops each time. This is why we normalize data into lookup tables — so any query
becomes a direct O(1) key access instead of a full traversal.
