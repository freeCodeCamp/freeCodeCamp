## Graphs Overview

A graph is a set of nodes (vertices) connected by edges (connections). Each node can connect to multiple other nodes, forming a network. The different types of graphs include:

- **Directed**: Edges have a direction (from one node to another), often represented with straight lines and arrows.
- **Undirected**: Edges have no direction, represented with simple lines.
- **Vertex labeled**: Each node is associated with a label or identifier.
- **Cyclic**: Contains cycles (a path that starts and ends at the same node).
- **Directed acyclic graph (DAG)**: A directed graph with no cycles.
- **Edge labeled**: Each edge has a label usually drawn next to the corresponding edge.
- **Weighted**: Edges have weights (values) associated with them that can be used to perform arithmetic operations.
- **Disconnected**: Contains two or more groups of nodes (components) that are not connected by any edges. Two nodes can lack a direct edge and still have a path between them.

Graphs are used in various applications such as maps, networks, recommendation systems, and dependency resolution.

## Graph Traversals

This involves visiting all the nodes in a graph. The two main algorithms are:

- **Breadth-First Search (BFS)**: Visits all neighboring nodes before moving to the next level in the graph.
  - **Queue**: Uses a queue (FIFO). The start node is marked as visited and added to the queue. While the queue is not empty, the current node is dequeued, and each of its unvisited neighbors is marked as visited and added to the queue.
  - **Shortest Path**: Finds shortest path in unweighted graphs.
  - **Memory**: Requires storing a queue in memory, so the space requirements can be considerable, especially for graphs with a large number of nodes on the same level.
  - **Connected Components**: Can also be used for finding connected graph components, by starting a new search from each node that has not been visited yet.
  - **State-Space Search**: Uses a queue to track different states as it builds the parentheses combinations. Each state is represented as an array containing the current string being built, the number of opening parentheses used so far, and the number of closing parentheses used so far. An opening parenthesis can only be added if the number of opening parentheses used is less than the number of pairs. A closing parenthesis can only be added if it maintains balance, meaning there must be more opening parentheses used than closing parentheses.

- **Depth-First Search (DFS)**: Follows each branch as deep as possible before it backtracks.
  - **Stack**: Uses a stack (LIFO) or recursion. The start node is marked as visited and added to the stack. While the stack is not empty, the current node is popped, and its unvisited neighbors are marked as visited and added to the stack.
  - **Memory**: Requires storing a stack (or the function call stack, when using recursion) in memory, so the space requirements can grow in graphs with very long paths.
  - **Use Cases**: Useful for cycle detection, path finding, and finding connected components.
  - **Limitation**: It's not always guaranteed to find the shortest path between two nodes in an unweighted graph.

## Graph Representations

Graphs can be represented in two main ways:

- **Adjacency List**: Each node has a list of its neighbors.
  - **Implementations**: As an array, where each index represents a node and the array stored at that index contains its neighbors. As an object (or `Map`), where each key represents a node and the value associated to that key (an array) contains its neighbors.
  - **Space**: Space efficient for sparse graphs, with a `O(V + E)` space complexity, where `V` is the number of vertices (nodes) and `E` is the number of edges.
  - **Neighbors**: Easy to iterate over neighbors, since this operation only requires accessing the list associated to the node.
  - **Edge Lookup**: Less efficient than adjacency matrices for determining if there is an edge between two nodes. It typically takes `O(deg(v))` time, where `deg(v)` is the number of neighbors of the node you're checking, and in the worst case it can be `O(V)`.
  - **Best For**: Usually the preferred choice for real-world scenarios, where sparse graphs are more common.

- **Adjacency Matrix**: A 2D array where rows and columns represent nodes.
  - **Values**: If the graph is unweighted, a value of `1` means that there is an edge connecting these nodes, while a value of `0` means there is no edge between them. If the graph is weighted, the value represents the weight of the edge that connects the nodes.
  - **Self-Loops**: The values in the diagonal represent whether or not each node has a self-loop, an edge that connects the node to itself.
  - **Space**: Space intensive for large graphs, with a large quadratic space requirement `O(V²)`, where `V` is the number of nodes in the graph.
  - **Edge Lookup**: Fast to check if an edge exists between two nodes, since it takes constant time `O(1)`.
  - **Neighbors**: Inefficient for finding a node's neighbors, because the program has to iterate over the entire row or column. In the worst case, this takes `O(V)` time.
  - **Best For**: Helpful for dense graphs with many edges. It is inefficient for sparse graphs, which only have a few edges.

## Shortest Path Algorithm

- **Shortest Path Algorithm**: Computes the shortest path between nodes in a weighted graph and returns both the distances and the paths taken.
  - **Adjacency Matrix**: Each value represents the weight (distance) of the edge between two nodes.
  - **Missing Edges**: A value of `INF` (`Infinity`) means there is no direct edge.
  - **Distances**: An array that keeps track of the shortest known distance from the start node to every other node. To begin, every node is assumed to be infinitely far away, and the distance from the start node to itself is always `0`.
  - **Paths**: A list where each entry is an array of node indices representing the route taken to reach each node.
  - **Visited**: An array that tracks which nodes have already been processed so you don't revisit them.
  - **Closest Unvisited Node**: The main loop runs once for each node in the graph, selecting the closest unvisited node each time.
  - **Edge Relaxation**: For each neighbor with an actual edge that has not been visited yet, check if you can reach it more efficiently through the current node. If the new distance is better than what's already stored, update the distance and the path.
  - **Unreachable Nodes**: When no valid node is found, all the remaining nodes are unreachable, so the loop stops early.
  - **Optional Target**: The `targetNode` parameter is optional. When not provided, the function computes shortest paths from `startNode` to all other nodes in the graph.

## Trees

A tree is a special type of graph that is acyclic and connected. Key properties include:

- **Acyclic**: A tree has no loops or cycles (paths where the start and end nodes are the same).
- **Connected**: Every node can be reached from every other node.

### Tree Terminology

- **Root Node**: The very top of a tree. It's the only node in the tree without a parent node.
- **Parent Node**: A node that is immediately connected to other nodes below it.
- **Child Node**: A node that is immediately connected to a node above it.
- **Leaf**: A node that has no child nodes.
- **Depth**: The length of the path from the root to that node.
- **Height**: The length of the path from that node down to a leaf. The height of a tree is the height of its root node.
- **Degree**: The number of child nodes each node has.
- **Subtree**: A section of a tree that is a tree itself.
- **Balanced Tree**: A tree in which the heights of the left and right subtrees of any node are very similar to make sure that operations remain efficient.

### Common Types of Trees

The most common types of trees are:

- **Binary Trees**: Each node has at most two children, a left and a right child.

- **Binary Search Trees (BST)**: A binary tree in which, for every node, all values in its left subtree are less than the node's value, and all values in its right subtree are greater than the node's value. The left and right subtrees must also be binary search trees themselves.

- **Self-Balancing Trees**: Trees that contain additional internal logic which re-balance the tree when insertions or deletions create a state of imbalance. Common examples include AVL trees, red-black trees, and B-trees.

- **AVL Trees**: A type of self-balancing binary search tree in which the heights of the left and right subtrees of any node differ by at most one.

- **Red-Black Trees**: A type of self-balancing binary search tree in which each node is colored red or black.

- **B-Trees**: A type of self-balancing tree in which each node can have multiple keys and more than two child nodes.

## Tries

- **Tries**: Also known as prefix trees, they are used to store sets of strings, where each node represents a character.
- **Root Node**: The root node does not represent any particular character, so you can think of it as representing an empty string.
- **Prefixes**: As you traverse the trie down from the root, the path to a node defines a specific prefix.
- **End-of-Word Markers**: Nodes that represent complete words are assigned end-of-word markers.
- **Shared Prefixes**: When multiple strings share the same prefix, their paths overlap, so the prefix itself is only stored once. This makes tries efficient for tasks like autocomplete and spell checking.
- **Insertion**: Only requires creating new nodes for the characters that don't exist in the trie yet.
- **Time Complexity**: Search and insertion operations take `O(L)` time, where `L` is the length of the string.
- **Memory**: Tries can be inefficient if the set of strings has many unique characters, because this requires storing many unique characters as individual nodes.

## Priority Queues

- **Priority Queue**: An abstract data type where each element has a priority.
- **Queues and Stacks**: Queues and stacks consider only the order of insertion, while priority queues consider the priority of elements. Standard queues follow FIFO (First In First Out) and stacks follow LIFO (Last In First Out).
- **Removal Order**: Usually, the element with the highest priority is removed first, but some implementations may also choose to remove the element with the lowest priority first.
- **Ties**: If you need elements with the same priority to be removed in the order that they were inserted, you could include a unique counter to break the tie.
- **Applications**: Finding the shortest path between two locations, scheduling tasks in operating systems, simulating traffic, compressing data, and managing networks.

## Heaps

A heap is a specialized tree-based data structure with a very specific property called the heap property.

The heap property determines the relationship between parent and child nodes. There are two types of heaps:

- **Max-Heap**: The value of each parent node is greater than or equal to the values of its children, and the largest element is at the root.

- **Min-Heap**: The value of each parent node is less than or equal to the values of its children, and the smallest element is at the root.


JavaScript doesn't have a built-in heap module, but you can implement a min-heap using an array.

- **Array Storage**: Heaps are typically implemented as arrays to access parent and child nodes efficiently. If the heap maintains the structure of a complete binary tree, the array implementation only requires simple mathematical operations based on the indices to find where the elements are located.
- **Indexes**: For the node at index `i`, the parent is at index `Math.floor((i - 1) / 2)`, the left child is at index `2 * i + 1`, and the right child is at index `2 * i + 2`.
- **Peek**: Getting the minimum or maximum value (depending on the type of heap) without removing it.
- **Push**: Adds an element where it should be, to preserve the heap property. The new element is added at the end of the array and then moved up, swapping places with its parent, until the heap property is preserved (bubble-up).
- **Pop**: Removes the element with the highest priority (in this case, the smallest value). The last element of the array replaces the root and is then moved down, swapping places with its smaller child, until the heap property is preserved (bubble-down).
- **PushPop**: Combines both operations into one call. This is more efficient than calling them in a sequence separately, especially when the heap is large, since it only performs one reordering operation.
- **Heapify**: Transforms an existing array into a heap.
- **Comparison Callback**: Arrays are not automatically compared element by element for ordering in JavaScript, so you pass a comparison function to the heap that compares priorities first, like `new MinHeap((a, b) => a[0] - b[0])` for items stored as `[priority, element]`. Lower values represent higher priorities.
- **Stable Tie Breaking**: Include an increasing insertion counter as the second element of each item, like this: `[priority, counter, element]`. Compare priorities first and then counters when priorities are equal: `new MinHeap((a, b) => (a[0] - b[0]) || (a[1] - b[1]))`.
- **Time Complexity**: Inserting and extracting the minimum or maximum value is `O(log n)`, peeking is `O(1)`, heapify is `O(n)`, and searching for or deleting an arbitrary element is `O(n)`.
- **Space Complexity**: `O(n)`, where `n` is the number of elements the heap contains.
