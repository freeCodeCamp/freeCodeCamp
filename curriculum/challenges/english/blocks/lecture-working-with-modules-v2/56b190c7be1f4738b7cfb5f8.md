# --description--

As you learned in the previous lesson, a module is a Python file that groups related code, so you can reuse it in other Python files.

You can also write your own modules and import them into your scripts. Creating your own modules is a great way to organize your code. Instead of having one very long file, you can split your code into smaller files, where each one groups related code, and then import them wherever you need them.

For example, suppose you created a `temperature.py` file with two functions for converting temperatures, and a function call to check that one of them works:

```python
# temperature.py
def celsius_to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

def fahrenheit_to_celsius(fahrenheit):
    return (fahrenheit - 32) * 5 / 9

print(celsius_to_fahrenheit(100))
```

If you run this file directly, this is the output:

```md
212.0
```

Now, suppose you create another file called `main.py` in the same folder as `temperature.py`. To use the functions from your local module, you import it using the name of the module without the `.py` extension:

```python
# main.py
import temperature

print(temperature.fahrenheit_to_celsius(212))
```

If you run the `main.py` file, this is the output:

```md
212.0
100.0
```

When `temperature` is imported, Python runs all the code in `temperature.py` from top to bottom. That's why `212.0` is printed, even though `main.py` only calls `fahrenheit_to_celsius()`. Code like this check is usually something you want to run only when you execute the file directly, not every time it's imported.

To control this, you can use a common Python idiom:

```python
if __name__ == '__main__':
    # Code
```

`__name__` is a special built-in variable in Python.

When a Python file is executed directly, Python sets the value of this variable to the string `__main__`.

But if the Python file is imported as a module into another Python script, the value of the `__name__` variable is set to the name of that module (usually the filename without the `.py` extension).

This is why you'll often find this conditional in Python scripts. It contains the code that you want to run **only if** the Python script is running as the main program. If the script is imported as a module, the code within that block doesn't run.

This is helpful because it allows Python scripts to have two purposes. They can be run directly to execute their main logic, or they can be imported into another module without executing their main logic.

Here is the `temperature.py` file updated to use this idiom. It also prints the value of `__name__`, so you can see how it changes:

```python
# temperature.py
def celsius_to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

def fahrenheit_to_celsius(fahrenheit):
    return (fahrenheit - 32) * 5 / 9

print(f'The value of __name__ is: {__name__}')

if __name__ == '__main__':
    print(celsius_to_fahrenheit(100))
```

If you run this file directly, Python sets `__name__` to `'__main__'`, so the condition is `True` and the code inside the `if` block runs. This is the output:

```md
The value of __name__ is: __main__
212.0
```

If you run the `main.py` file instead, this is the output:

```md
The value of __name__ is: temperature
100.0
```

The `print()` call outside of the `if` block still runs when `temperature` is imported, and shows that the value of `__name__` is now `temperature`, the name of the module.

But since `__name__` is not equal to `'__main__'`, the code inside the `if` block doesn't run, so `212.0` is not printed. The only other output is `100.0`, which comes from the function call in `main.py`.
