# --description--

You have learned how to create dictionaries and access and update their values. Now you will use dictionary methods, copy dictionaries, and explore how functions can change them.

Each dictionary method example below starts with this dictionary:

```python
pizza = {
    'name': 'Margherita',
    'price': 8.9,
    'calories_per_slice': 250,
    'toppings': ['mozzarella', 'basil']
}
```

## Dictionary Methods

Dictionaries also have helpful methods to perform common operations.

The `.get()` method retrieves the value associated with a key. It's similar to the bracket notation you learned in the previous lesson, but its advantage is that you can set a default value, so you won't get an error if the key doesn't exist:

```python
dictionary.get(key, default)
```

In this example, if the `toppings` key doesn't exist, it will return an empty list, which is the default value that we are passing here as the second argument. But if `toppings` does exist, it will return that value:

```python
pizza.get('toppings', []) # ['mozzarella', 'basil']
```

The `.keys()` and `.values()` methods return a view object with all the keys and values in the dictionary, respectively:

```python
pizza.keys()
# dict_keys(['name', 'price', 'calories_per_slice', 'toppings'])

pizza.values()
# dict_values(['Margherita', 8.9, 250, ['mozzarella', 'basil']])
```

A view object is just a way to see the content of a dictionary without creating a separate copy of the data.

The `.items()` method returns a view object with all the key-value pairs in the dictionary, including both the keys and the values:

```python
pizza.items()
# dict_items([('name', 'Margherita'), ('price', 8.9), ('calories_per_slice', 250), ('toppings', ['mozzarella', 'basil'])])
```

The `.clear()` method removes all the key-value pairs from the dictionary:

```python
pizza.clear()
```

The `.pop()` method removes the key-value pair with the key that you specify as the first argument and returns its value. If the key doesn't exist, it returns the default value that you specify as the second argument. If the key doesn't exist and you don't pass a default value, a `KeyError` is raised:

```python
pizza.pop('price', 10)
pizza.pop('total_price') # KeyError
```

In Python 3.7 and more recent versions, the `.popitem()` method removes the last inserted item:

```python
pizza.popitem()
```

The `.update()` method updates the key-value pairs with the key-value pairs of another dictionary. If they have keys in common, their values are overwritten.

In this example, we are updating the `pizza` dictionary. The `price` key exists in both of them, so its value will be replaced with `15`.

But `total_time` is new, so it will be added to the `pizza` dictionary as a new key-value pair:

```python
pizza.update({ 'price': 15, 'total_time': 25 })
```

This is the new dictionary with the updated `price` and the new `total_time`. Notice how the price is now `15` and `total_time` is a new key-value pair:

```python
{
    'name': 'Margherita',
    'price': 15,
    'calories_per_slice': 250,
    'toppings': ['mozzarella', 'basil'],
    'total_time': 25
}
```

### Assignment and Shallow Copies

As you learned with lists, assigning a dictionary to another variable creates an alias. Both names refer to the same object:

```python
settings = {'theme': 'light', 'languages': ['English']}
alias = settings
alias['theme'] = 'dark'

print(settings['theme']) # dark
print(alias is settings) # True
```

To create a separate outer dictionary, use the `.copy()` method:

```python
settings = {'theme': 'light', 'languages': ['English']}
copied_settings = settings.copy()
copied_settings['theme'] = 'dark'

print(settings['theme']) # light
print(copied_settings['theme']) # dark
print(copied_settings is settings) # False
```

Replacing an entry in `copied_settings` does not replace the corresponding entry in `settings`. However, `.copy()` makes a **shallow copy**: it creates a new outer dictionary whose keys and values refer to the same objects as those in the original dictionary. Nested mutable objects are still shared:

```python
settings = {'theme': 'light', 'languages': ['English']}
copied_settings = settings.copy()

print(copied_settings is settings) # False
print(copied_settings['languages'] is settings['languages']) # True

copied_settings['languages'].append('Spanish')
print(settings['languages']) # ['English', 'Spanish']
print(copied_settings['languages']) # ['English', 'Spanish']
```

The two dictionaries are different objects, but their `languages` entries refer to the same list. Appending to that list is visible through both dictionaries. Replacing `copied_settings['languages']` with a new list would instead change only that entry in the copy.

You can also create a shallow copy by passing a dictionary to `dict()`:

```python
settings = {'theme': 'light', 'languages': ['English']}
copied_settings = dict(settings)

print(copied_settings is settings) # False
print(copied_settings['languages'] is settings['languages']) # True
```

Like `.copy()`, `dict(settings)` creates a new outer dictionary, but the nested list is still shared. Replacing an entry in either dictionary affects only that dictionary, while changing the shared list is visible through both.

## Mutating a Dictionary through a Function Parameter

The same argument-passing rules you learned with lists apply to dictionaries. A parameter initially refers to the object passed as an argument. Updating an entry through that parameter mutates the shared dictionary:

```python
def set_theme(settings, theme):
    settings['theme'] = theme
    return 'Theme updated'

preferences = {'theme': 'light'}
status = set_theme(preferences, 'dark')

print(status) # Theme updated
print(preferences) # {'theme': 'dark'}
```

The function returns a status string, while `preferences` changes through the shared reference. Returning a value and mutating an object are separate effects. The function does not need to return the dictionary for the changes to be visible outside the function. Reassigning the local parameter to a different dictionary would not replace the dictionary referenced by `preferences`.

## Using a Dictionary as a Default Argument

Recall that a default list is created when the function is defined and reused across calls that omit the argument. A default dictionary behaves the same way:

```python
def add_setting(key, value, settings={}):
    settings[key] = value
    return settings

print(add_setting('theme', 'dark')) # {'theme': 'dark'}
print(add_setting('language', 'English')) # {'theme': 'dark', 'language': 'English'}
```

The second call reuses the dictionary changed by the first call. This means settings accumulate across independent calls, even though each call has its own local parameter name.

When each call should start with a fresh dictionary, use the `None` default pattern:

```python
def add_setting(key, value, settings=None):
    if settings is None:
        settings = {}
    settings[key] = value
    return settings

print(add_setting('theme', 'dark')) # {'theme': 'dark'}
print(add_setting('language', 'English')) # {'language': 'English'}

preferences = {}
add_setting('theme', 'dark', preferences)
print(preferences) # {'theme': 'dark'}
```

Each call that omits `settings`, or passes `None`, creates a fresh dictionary. Passing an existing dictionary still lets the function mutate that object. Use `settings is None` here: `if not settings` would also match an empty dictionary passed as an argument and replace it with a new local dictionary.
